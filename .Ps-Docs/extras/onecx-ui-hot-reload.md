# OneCX UI Hot Reload Integration Guide

This guide explains how to set up hot reload for rapid development of OneCX UI microfrontends. With hot reload, changes in your local Angular app are reflected immediately without rebuilding Docker images.

## Overview

Hot reload works by:
1. Registering the product and UI with OneCX using `@onecx/local-env-cli`
2. Running your Angular app locally with `npm start` bound to `0.0.0.0`
3. Using `toggle-mfes.sh` to route Traefik requests to your local dev server instead of the Docker container
4. Module Federation loads `remoteEntry.js` from the live dev server

## Prerequisites

- OneCX local environment running (`onecx-local-env`)
- Your UI project (Angular + Module Federation) with `proxy.conf.js`
- `@onecx/local-env-cli` available (`npx @onecx/local-env-cli`)
- Understanding of your app's routing path (e.g., `/mfe/bookCatalog/`)

## Directory Structure for Hot Reload

```
onecx-local-env/
├── init-data/
│   └── traefik/
│       ├── inactive/
│       │   └── _mfe_template.yml    # Template used by toggle-mfes.sh
│       └── active/
│           └── <mfe-name>_<port>.yml  # ⭐ Auto-generated by toggle-mfes.sh
└── <product-name>.compose.yaml      # Docker compose (image/build commented for hot reload)
```

## Parameters

Throughout this guide, replace these with your actual values:

| Parameter | Description | Example |
|-----------|-------------|---------|
| `<product-name>` | Product identifier, used in CLI commands and compose files | `test-book-app` |
| `<mfe-name>` | MFE name as registered in product-store (camelCase) | `bookCatalog` |
| `<mfe-path>` | URL path under `/mfe/` | `bookCatalog` → `/mfe/bookCatalog/` |
| `<menu-path>` | Menu entry path in workspace | `/test-book-app/book-c` |
| `<menu-label>` | Display name shown in the shell menu | `Test Book App` |
| `<port>` | Local dev server port | `4200` |
| `<env-path>` | Absolute path to `onecx-local-env` folder | `/root/onecx/dev-new/onecx-local-env` |

## Step-by-Step Setup

### Step 1: Register the Product and UI with OneCX

Use the CLI to sync the UI, create menu entry, and Docker compose file. This registers the product, MFE, permissions, and workspace entries.

```bash
# First: Sync the UI project to create product/MFE/permissions
npx @onecx/local-env-cli sync ui <product-name> /<base-path> ./helm/values.yaml \
  -e <env-path> \
  -n <product-name>-ui

# Second: Create menu entry in OneCX workspace
npx @onecx/local-env-cli menu create <product-name>-ui <menu-path> "<menu-label>" \
  -e <env-path>

# Third: Create the Docker compose file for this product
npx @onecx/local-env-cli docker <product-name> create <product-name> <mfe-name> \
  -e <env-path> \
  -s ui
```

**Example (test-book-app):**
```bash
npx @onecx/local-env-cli sync ui test-book-app /test-book-app ./helm/values.yaml \
  -e /root/onecx/dev-new/onecx-local-env \
  -n test-book-app-ui

npx @onecx/local-env-cli menu create test-book-app-ui /test-book-app/book-c "Test Book App" \
  -e /root/onecx/dev-new/onecx-local-env

npx @onecx/local-env-cli docker test-book-app create test-book-app bookCatalog \
  -e /root/onecx/dev-new/onecx-local-env \
  -s ui
```

This generates `<env-path>/<product-name>.compose.yaml` with image + build + Traefik labels configured.

### Step 1b: Register Product to the ADMIN Workspace

> ⚠️ **This step is required and is NOT handled automatically by the CLI or `import-onecx.sh`.**
>
> The workspace ExIm import **skips workspaces that already exist** in the database — it returns `"ADMIN": "SKIPPED"` every time. This means the product registration and menu entry from Step 1 are never actually applied to a running environment. You must register manually.

Three things must exist in the workspace database for your UI to appear in the shell:

1. **Product** — registers `<product-name>` under the ADMIN workspace with a base URL
2. **Menu item** — adds the navigation entry under "Custom Applications"
3. **Role assignment** — grants `onecx-admin` visibility of the menu item (without this the menu entry is invisible)

**Use the provided script** (works for any product, idempotent — safe to re-run):

```bash
cd <env-path>
./scripts/register-product-to-workspace.sh \
  -p <product-name> \
  -b /<product-name> \
  -m <mfe-id> \
  -k CUSTOM_<PRODUCT_NAME_UPPER>_UI \
  -n "<Menu Label>" \
  -u /<product-name>
```

| Parameter | Description | Example |
|-----------|-------------|---------|
| `-p` | Product name | `book-catalog` |
| `-b` | Base URL (must match product-store `basePath`) | `/book-catalog` |
| `-m` | MFE app ID (second segment of `<product>_<appid>_main.json` filename) | `book-catalog` |
| `-k` | Unique menu item key | `CUSTOM_BOOK_CATALOG_UI` |
| `-n` | Display name in the shell menu | `"Book Catalog"` |
| `-u` | Menu URL — **must be a valid route in your Angular app** | `/book-catalog` |

> **Note on menu URL:** Use just the workspace base URL (e.g. `/book-catalog`) to load the app at its default route. Using a sub-route like `/book-catalog/main` will show a blank screen if that route does not exist in your Angular router.

**Example (book-catalog):**
```bash
cd /root/onecx/dev-new/onecx-local-env
./scripts/register-product-to-workspace.sh \
  -p book-catalog \
  -b /book-catalog \
  -m book-catalog \
  -k CUSTOM_BOOK_CATALOG_UI \
  -n "Book Catalog" \
  -u /book-catalog
```

**Alternative: register via the workspace UI**
1. Go to `http://onecx.localhost/onecx-shell/admin/workspace/ADMIN` → **Applications** tab
2. Select your product in the left list → click **→** to move it to Registered Applications
3. Save, then add the menu item manually under **Menu** tab

> This step applies equally to **hot reload** and **Docker image** deployments — it is a workspace database concern, not a deployment mode concern.

### Step 2: Prepare the Compose File for Hot Reload

The CLI-generated compose file starts the UI as a Docker container. For hot reload, comment out the `image`/`build` block **and** the Traefik labels (Traefik routing will be handled by `toggle-mfes.sh` instead).

Also, **add `- base`** to the profiles — the CLI only generates `- all`, but you need both to work with `./start-onecx.sh -p base`:

```yaml
services:
  <product-name>-ui:
    # image: ${<PRODUCT_NAME>_UI}        # commented: not using Docker image for hot reload
    # build:                             # commented: not building image for hot reload
    #   context: /path/to/your-ui-project
    #   dockerfile: Dockerfile
    container_name: <product-name>-ui
    environment:
      APP_BASE_HREF: /mfe/<mfe-path>/
      APP_ID: <product-name>-ui
      PRODUCT_NAME: <product-name>
      BFF_URL: "http://localhost:8080"
    # labels:                            # commented: Traefik routing handled by toggle-mfes.sh
    #   - traefik.http.services...
    #   - traefik.http.routers...
    networks:
      - onecx
    profiles:
      - all
      - base                            # ⭐ ADD THIS - CLI only generates 'all'
```

> **Note:** Keep all lines — just comment out the `image`, `build`, and `labels` blocks. Do not delete them so you can re-enable Docker image mode later. **Add `- base`** to profiles if missing.

### Step 3: Activate Traefik Hot Reload Routing

Use `toggle-mfes.sh` to generate the Traefik config file. **Do not create the file manually** — the script uses the template in `init-data/traefik/inactive/_mfe_template.yml` to ensure correct structure.

```bash
cd <env-path>
./toggle-mfes.sh -a <mfe-name>:<port>:/mfe/<mfe-path>
```

**Parameter breakdown for `-a <mfe-name>:<port>:/mfe/<mfe-path>`:**

| Part | What it is | Example |
|------|-----------|--------|
| `<mfe-name>` | Identifier used for Traefik service/router/middleware names. Should match MFE registration. | `bookCatalog` |
| `<port>` | Port your dev server is listening on | `4200` |
| `:/mfe/<mfe-path>` | Full URL prefix registered in OneCX product-store. Must start with `/mfe/`. | `/mfe/bookCatalog` |

The script:
1. Copies `_mfe_template.yml` substituting `{{MFE_NAME}}`, `{{MFE_PORT}}`, `{{MFE_PATH}}`, `{{MFE_STRIPPATH}}`
2. Writes the result to `init-data/traefik/active/<mfe-name>_<port>.yml`
3. Traefik **auto-detects** the new file — no restart needed

The generated config:
- **Router**: matches `Host(onecx.localhost) && PathPrefix(/mfe/<mfe-path>/)` at priority 323 (overrides any Docker container labels)
- **Middleware**: strips `/mfe/<mfe-path>` prefix before forwarding — so `/mfe/bookCatalog/remoteEntry.js` becomes `/remoteEntry.js` on the dev server
- **Service**: forwards to `http://host.docker.internal:<port>/` (resolves to host machine from inside Docker)

**Example:**
```bash
cd /root/onecx/dev-new/onecx-local-env
./toggle-mfes.sh -a bookCatalog:4200:/mfe/bookCatalog
# Output: bookCatalog_4200  ✔  mapping: /mfe/bookCatalog/ => localhost:4200
```

Other toggle-mfes.sh operations:
```bash
./toggle-mfes.sh -l                          # list all active configs
./toggle-mfes.sh -d <mfe-name>:<port>        # deactivate one
./toggle-mfes.sh -c                          # remove all
```

### Step 4: Configure proxy.conf.js

Your `proxy.conf.js` must handle the MFE path rewrite so the dev server receives requests at `/` instead of `/mfe/<mfe-path>/`:

```javascript
const bypassFn = function (req, res) {
  try {
    if (req.method === 'OPTIONS') {
      res.setHeader('Allow', 'GET, POST, HEAD, PUT, DELETE, OPTIONS');
      res.setHeader('Access-Control-Allow-Origin', '*');
      res.setHeader('Access-Control-Allow-Methods', '*');
      res.setHeader('Access-Control-Allow-Headers', '*');
      return res.send('');
    } else {
      return null;
    }
  } catch (error) {
    console.log('error', error);
  }
};

const PROXY_CONFIG = {
  '/mfe/<mfe-path>': {
    target: 'http://localhost:<port>/',
    secure: false,
    pathRewrite: {
      '^.*/mfe/<mfe-path>': '',
    },
    changeOrigin: true,
    logLevel: 'debug',
    bypass: bypassFn,
  },
  '/bff': {
    target: 'http://<product-name>-bff',
    secure: false,
    pathRewrite: {
      '^.*/bff': '',
    },
    changeOrigin: true,
    logLevel: 'debug',
    bypass: bypassFn,
  },
};

module.exports = PROXY_CONFIG;
```

### Step 5: Start the Dev Server with `--host 0.0.0.0`

**Critical:** The dev server must bind to `0.0.0.0` (not `127.0.0.1`) so Traefik can reach it via `host.docker.internal`. Pass this as a CLI flag at runtime — do **not** modify `project.json` to hardcode it.

```bash
cd /path/to/your-ui-project
npm start -- --host 0.0.0.0 --port <port> --disable-host-check
```

If your `package.json` start script calls `nx serve` directly you can also use:
```bash
npx nx serve --host 0.0.0.0 --port <port> --disable-host-check
```

Verify the binding — it must show `0.0.0.0`, **not** `127.0.0.1`:
```bash
ss -tlnp | grep <port>
# Expected: LISTEN  0.0.0.0:<port>
# Wrong:    LISTEN  127.0.0.1:<port>  ← Traefik cannot reach this
```

### Step 6: Verify

```bash
# Test remoteEntry.js is served through Traefik
curl -H "Host: onecx.localhost" http://localhost/mfe/<mfe-path>/remoteEntry.js
# Expect: HTTP 200 with JS content
```

Then open `http://onecx.localhost/onecx-shell/admin/` in your browser.

## Disabling Hot Reload (Switch Back to Docker Image)

```bash
cd <env-path>
./toggle-mfes.sh -d <mfe-name>:<port>
```

Then uncomment the `image`/`build`/`labels` blocks in your compose file.

## Known Issues and Lessons Learned

### `include:` in compose file does not load services

**Symptom:** `docker compose -f <product>.compose.yaml config` shows `services: {}` — your service is invisible.

**Cause:** Docker Compose resolves `include:` path relative to the file, but network/profile context is not inherited properly in this setup.

**Fix:** Never use `include:` in your product compose file. Use multiple `-f` flags instead:
```bash
docker compose -f versions/v2/compose.yaml -f <product-name>.compose.yaml --profile base up -d
```

### Profile mismatch — service never starts

**Symptom:** Running `./start-onecx.sh -p base` or `--profile base` but the service never starts.

**Cause:** The CLI-generated compose file sets `profiles: [all]` only. With `--profile base`, that service is excluded.

**Fix:** Add both profiles:
```yaml
profiles:
  - all
  - base
```

### 502 Bad Gateway — dev server not reachable

**Symptom:** `http://onecx.localhost/mfe/<mfe-path>/remoteEntry.js` returns 502.

**Root cause:** Dev server is bound to `127.0.0.1` (loopback only). Traefik runs inside Docker and connects via `host.docker.internal` (resolves to e.g. `172.17.0.1`) — which cannot reach `127.0.0.1`.

**Diagnosis:**
```bash
ss -tlnp | grep <port>
# 127.0.0.1:<port> = broken, 0.0.0.0:<port> = correct
```

**Fix:** Always pass `--host 0.0.0.0` at startup. Do not rely on `project.json` defaults.

### Manually created Traefik file missing path strip middleware

**Symptom:** 502 or 404 even though dev server is running. Traefik forwards `/mfe/bookCatalog/remoteEntry.js` and the dev server has no route for that path.

**Cause:** Manually created traefik config lacked the `stripPrefix` middleware, so the full `/mfe/bookCatalog/` path was forwarded instead of `/`.

**Fix:** Always use `./toggle-mfes.sh -a` — it generates the correct middleware from the template automatically.

### `host.docker.internal` resolution on Linux

On Linux, `host.docker.internal` is not automatically added by Docker. Verify it resolves from inside the Traefik container:
```bash
docker exec traefik getent hosts host.docker.internal
# Should return something like: 172.17.0.1  host.docker.internal
```
If missing, add `extra_hosts: ["host.docker.internal:host-gateway"]` to the traefik service in compose.

## Troubleshooting

### Bad Gateway (502)

**Most common cause:** Dev server bound to `127.0.0.1` instead of `0.0.0.0`.

Check:
```bash
ss -tlnp | grep <port>
```

Fix — always start with explicit host:
```bash
npm start -- --host 0.0.0.0 --disable-host-check
```

Do **not** modify `project.json` to set the host permanently — pass it as a flag at runtime.

### host.docker.internal Does Not Resolve

On Linux, `host.docker.internal` may need to be added to your Docker daemon or compose file. Verify from within the Traefik container:

```bash
docker exec traefik getent hosts host.docker.internal
# Should return the host IP (e.g., 172.17.0.1)
```

### Traefik Config Not Picked Up

Check that your file is in `init-data/traefik/active/` (not `inactive/`). Traefik watches this directory and reloads automatically. List active configs:

```bash
./toggle-mfes.sh -l
```

### Deactivate and Re-activate

If routing seems wrong, deactivate and re-activate:

```bash
./toggle-mfes.sh -d <mfe-name>:<port>
./toggle-mfes.sh -a <mfe-name>:<port>:/mfe/<mfe-path>
```

### "Failed to fetch dynamically imported module"

Module Federation can't load the remote. Check:
1. Dev server is running: `curl http://localhost:<port>/remoteEntry.js`
2. Traefik routing: visit `http://localhost:8082/dashboard/`
3. CORS: ensure `proxy.conf.js` handles OPTIONS requests

## Running Multiple Apps Simultaneously

Each app needs a unique port and its own traefik config:

```bash
./toggle-mfes.sh -a <app1>:<port1>:/mfe/<path1>
./toggle-mfes.sh -a <app2>:<port2>:/mfe/<path2>
```

List all active:
```bash
./toggle-mfes.sh -l
```

Remove all:
```bash
./toggle-mfes.sh -c
```
